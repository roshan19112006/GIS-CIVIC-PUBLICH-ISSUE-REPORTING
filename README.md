# GIS-Based Civic Issue Reporting Platform

An enterprise-grade, full-stack municipal complaint tracking and geospatial resolution web application developed for college Full Stack Development (FSD) projects.

Built with **React.js + Vite**, **Node.js + Express.js**, **MySQL**, **Leaflet.js**, **OpenStreetMap**, and **JWT Authentication**.

---

## 🌟 Key Capabilities & Features

### 1. Citizen Portal
- **Registration & Authentication**: Secure JWT session handling with bcrypt password hashing.
- **Geotagged Issue Reporting**:
  - Browser Geolocation API ("Use GPS Location") with high-accuracy fallback.
  - Interactive Leaflet map picker (click anywhere on the map to pin latitude & longitude).
  - Reverse geocoding via OpenStreetMap Nominatim with automatic address resolution.
  - Image upload with client- and server-side MIME type and 5MB size validation.
- **Unique Ticket Generation**: Autogenerated ticket IDs formatted as `TKT-YYYYMMDD-XXXX`.
- **Complaint Tracking & Timelines**: Full chronological timeline with changer roles, remarks, and timestamps.
- **Resolution Verification & Rating**: Inspect field officer's physical completion photograph, submit 1–5 star ratings, or reopen complaints if resolution is unsatisfactory.

### 2. Field Officer Operations
- **Work Orders Queue**: Filter assigned tasks by status (`assigned`, `in_progress`, `completed`), priority, and ward.
- **Interactive Geospatial Task Map**: View assigned complaint pins with popups and direct navigation.
- **Work Order Acceptance**: One-click transition from `assigned` to `in_progress`.
- **Mandatory Completion Proof**: Upload completion photograph and detailed resolution notes before marking resolved.
- **Department Referral**: Refer tasks to other departments with recorded reasons.

### 3. Municipal Administration Hub
- **KPI Metrics**: Real database counts for Total Complaints, Pending, In Progress, Resolved, SLA Breaches, and Citizen Ratings.
- **Visual Analytics (Recharts)**:
  - Issues by Category (Pie Chart)
  - Complaints by Ward (Bar Chart)
  - Officer Performance & Completion Rankings
- **Complaint Dispatch**: Assign complaints to departments and field officers with customized SLA deadlines and instructions.
- **GIS Map & Issue Heatmap**: Toggle between individual marker pins and issue density heatmap.
- **RFC 4180 CSV Export**: One-click download of all filtered civic complaints.
- **Security & Audit Logs**: Immutable audit trail for user logins, assignments, and status transitions.

## 🗄️ Relational Database Schema (`gis_civic_platform`)

The database consists of **12 normalized relational tables**:

1. `users`: System users with roles (`admin`, `officer`, `citizen`), department, ward, and badge numbers.
2. `departments`: Municipal departments (Roads, Sanitation, Water, Electrical, Health).
3. `wards`: City jurisdiction boundaries, ward numbers, and GeoJSON coordinates.
4. `issue_categories`: Issue classifications, default departments, priorities, and SLA hour targets.
5. `issues`: The primary complaints table with latitude, longitude, address, priority, status, and deadlines.
6. `issue_images`: Uploaded complaint and resolution photographs.
7. `work_orders`: Officer dispatch assignments, instructions, and acceptance/completion timestamps.
8. `issue_status_history`: Complete audit log of every status transition with user remarks.
9. `resolutions`: Mandatory completion proof, resolution notes, and completion photo URLs.
10. `feedback`: Citizen 1–5 star ratings, satisfaction indicator, and reopen request details.
11. `notifications`: In-app notification alerts for citizens, officers, and administrators.
12. `audit_logs`: Security and administrative action logs with IP addresses and JSON payloads.

## 🚀 Setup & Execution Instructions

### Prerequisites
1. **Node.js** (v18.0 or higher)
2. **MySQL / MariaDB** (via XAMPP, MySQL Server, or Docker)

---

### Step 1: Database Setup
1. Ensure your MySQL service is running on `127.0.0.1:3306`.
2. Create and populate the database using the SQL scripts:

Using XAMPP MySQL CLI:
```bash
# In Windows Command Prompt / PowerShell:
C:\xampp\mysql\bin\mysql.exe -u root < database\schema.sql
C:\xampp\mysql\bin\mysql.exe -u root < database\seed.sql
```

Alternatively, run the automated Node database initializer:
```bash
cd backend
node config/initDb.js
```

---

### Step 2: Backend Configuration & Startup
1. Navigate to the `backend` folder:
   ```bash
   cd backend
   ```
2. Verify or create `backend/.env`:
   ```env
   PORT=5000
   NODE_ENV=development
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=
   DB_NAME=gis_civic_platform
   JWT_SECRET=super_secret_jwt_key_civic_gis_2026_xyz
   JWT_EXPIRES_IN=7d
   CLIENT_ORIGIN=http://localhost:5173
   MAX_FILE_SIZE=5242880
   ```
3. Install dependencies:
   ```bash
   npm install
   ```
4. Start the Express server:
   ```bash
   npm start
   # Or for development with auto-reload:
   npm run dev
   ```
   Server will listen on: `http://localhost:5000`

5. (Optional) Run the automated API test suite:
   ```bash
   npm test
   ```

---

### Step 3: Frontend Setup & Startup
1. In a separate terminal, navigate to the `frontend` directory:
   ```bash
   cd frontend
   ```
2. Install dependencies:
   ```bash
   npm install
   ```
3. Start the Vite development server:
   ```bash
   npm run dev
   ```
4. Open your browser and navigate to:
   ```
   http://localhost:5173
   ```

## 🔄 Complete Complaint Lifecycle Verification

To demonstrate the full workflow during your project review:

1. **Submit Complaint (Citizen)**:
   - Log in as `citizen@gmail.com` / `Password@123`.
   - Click **"Report Issue"**.
   - Upload an issue photograph.
   - Click on the interactive map or click **"Use GPS Location"** to capture coordinates.
   - Enter a title and description, then submit.
   - Note the generated Ticket ID (e.g. `TKT-20261022-XXXX`).

2. **Admin Dispatch (Administrator)**:
   - Log in as `admin@civic.gov` / `Password@123`.
   - On the Admin Dashboard, locate the newly submitted pending complaint.
   - Click **"Assign"**, choose the Department and Officer, set the priority and deadline, and submit.
   - The status updates to `assigned`.

3. **Field Work & Resolution (Field Officer)**:
   - Log in as `officer.roads@civic.gov` / `Password@123`.
   - On the Officer Dashboard, locate the work order.
   - Click **"Accept & Start Work"** (status becomes `in_progress`).
   - Click **"Complete & Resolve"**.
   - Upload the completion proof photograph and enter detailed resolution notes.
   - The status updates to `resolved`.

4. **Review & Verification (Citizen)**:
   - Log back in as `citizen@gmail.com`.
   - Receive the in-app notification: *"Complaint Resolved — Please Verify & Rate"*.
   - Click **"Rate Resolution"** on the complaint card.
   - Inspect the officer's resolution photograph side-by-side with the original complaint photo.
   - Submit a 5-star rating (or select unsatisfied to trigger a ticket reopening).

## 📡 REST API Documentation

### Authentication
- `POST /api/auth/register` — Register a new citizen account
- `POST /api/auth/login` — Sign in and obtain JWT token
- `GET /api/auth/me` — Retrieve active user profile

### Civic Issues
- `GET /api/issues` — Query complaints with multi-attribute filtering & pagination
- `GET /api/issues/:id` — Get complete issue details, photos, work orders, timeline, and reviews
- `POST /api/issues` — Create a new complaint with coordinates and photo upload (`multipart/form-data`)
- `PUT /api/issues/:id` — Update issue metadata
- `DELETE /api/issues/:id` — Delete an issue (Admin only)

### Workflow Operations
- `POST /api/issues/:id/assign` — Assign work order to department and officer (Admin only)
- `PUT /api/issues/:id/status` — Update complaint status (`in_progress`, etc.)
- `POST /api/issues/:id/resolution` — Record resolution notes and upload completion proof photograph
- `POST /api/issues/:id/refer` — Refer complaint to another department with reason
- `POST /api/issues/:id/feedback` — Submit citizen 1–5 star rating and optional reopening request
- `GET /api/issues/:id/history` — Get chronological status transition history

### GIS & Geospatial
- `GET /api/gis/issues` — Returns GeoJSON FeatureCollection of complaint markers
- `GET /api/gis/heatmap` — Returns weighted `[lat, lng, intensity]` points for density visualization

### Dashboard & Analytics
- `GET /api/dashboard/stats` — Live counts of complaints, SLA compliance %, and citizen ratings
- `GET /api/dashboard/analytics` — Categorical, ward, and officer performance distributions

### Reports & Security
- `GET /api/reports/issues.csv` — Download RFC 4180 CSV export of filtered issues
- `GET /api/audit-logs` — Query immutable system audit logs (Admin only)
- `GET /api/notifications` — Get user in-app notifications
- `PUT /api/notifications/:id/read` — Mark notification as read
- `PUT /api/notifications/read-all` — Mark all notifications as read

## 🛡️ Security Implementation
- **Parameterized Queries**: All database queries utilize parameter binding in `mysql2` to prevent SQL Injection.
- **Password Security**: Passwords hashed with `bcryptjs` (salt rounds: 10).
- **Role-Based Access Control (RBAC)**: Enforced on the server for all routes. Citizens cannot access other citizens' records or dispatch work orders; officers can only manage their assigned work orders.
- **Upload Hardening**: Restricts uploads to JPEG, PNG, and WebP formats with a 5MB size limit.
- **Rate Limiting**: Protects against brute-force authentication attacks.
